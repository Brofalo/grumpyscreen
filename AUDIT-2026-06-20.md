# grumpyscreen pre-fresh-cut audit — 2026-06-20

A deep comb of the whole `src/` tree (the Pono code; vendored lvgl/libhv/fmt/
wpa were out of scope) ahead of cutting a fresh OS build. Ten dimensions were
combed: crashes, state-visibility, the manual-temp ask, cleanup, build, printer
safety, performance, visual/copy craft, touch ergonomics, and filesystem edges.

**Verification note:** every fix below was made by inspection and is structurally
sound, but this Windows box cannot cross-compile the device target. The branch
needs a build + a bench flash (Jack) to confirm. Nothing here was glass-verified.

Branch: `feat/pono-calibrate`.

---

## FIXED (committed)

### batch 1 — crash + boot-killers · `ce4110f`
- **ws thread-safety**: a `recursive_mutex` now guards the RPC callback/consumer
  maps and the id allocation. Before this they were mutated by the ws thread
  (`onmessage`) and the UI thread (button taps) with no lock — a data race that
  could corrupt the maps and crash. Held only for brief critical sections and
  always released before any callback runs, so it can't invert with `lv_lock`.
- **erase-before-invoke** in `onmessage`: a callback that re-enters `send_jsonrpc`
  was invalidating the iterator used to erase it (use-after-free).
- **try/catch around `onmessage`**: a malformed frame (`json::parse`) or an
  unexpected JSON type (`get<>()`) no longer aborts the ws thread.
- **theme parse**: corrupt/empty theme JSON falls back to defaults instead of
  bricking boot; `ThemeConfig::get` is non-throwing and non-mutating.
- **wpa_event**: `return` after a NULL monitor io (was a guaranteed deref crash).
- **spoolman** `archived`, **utils** `getifaddrs`/`socket`/`ioctl`, and the
  `unregister_notify_update` two-arg erase (was `erase(end())` UB) all guarded.

### batch 2 — printer safety + always-show-state · `43a65f4`
- **cold-extrude gate**: the live Filament Extrude/Retract (raw `G1 E`) now refuse
  below 170C with a clear prompt, so a stray tap can't grind cold filament / strip
  the drive gear; they also show a busy overlay while running.
- **nozzle ceiling 330C → 300C** on the Temps steppers and keypad (over rating).
- **stuck-scrim watchdog**: `busy_show` arms a 180s one-shot timer that force-drops
  the "working" overlay if the completion reply never arrives (Klipper error on an
  open socket, a macro that never returns), so the operator is never stranded.
- **provisional cal overlay** so the glass shows "Starting calibration..." instead
  of "Ready" while the bed heats and the head homes.

### batch 3 — the manual-temp ask + more visibility · `ba65602`
- **Filament manual temp (the original request)**: tap the nozzle readout to type
  an exact target on the keypad; the PLA/PETG/PA-CF presets stay. Clamped to 300C.
- **Pause/Resume** show "Pausing..."/"Resuming..." during the park/unpark move.
- **Restart Klipper / Firmware / Reboot / Shutdown** show what's underway (they
  drop the link, so the screen was going silent until reconnect).
- **Print start** only returns home when Moonraker accepts it; on error it stays
  put and shows why, instead of pretending the print began.

### batch 4 — boot / reconnect robustness · `0a6fbd6`
- **connect epoch guard**: a reply in flight from a dropped link can no longer hide
  the boot screen and strand a cockpit over a dead connection.
- **no boot-hang** if `printer.objects.list` returns empty/error (was stuck at 78%).
- safe `server.info` parse; `~InitPanel` takes `lv_lock`.

### batch 5 — remaining callback-throw + overflow guards · `3cf5fac`
- console non-string param, `get_thumbnail` width parse, and the spoolman draw
  callback's id/color stoul all guarded against throwing into the ws/render paths.
- Files list filename clamps + ellipsizes (`LONG_DOT`) instead of running through
  the play icon.

### batch 6 — legibility, touch, copy · `2a1c366`
- `color_text_tertiary` raised to ~4.6:1 (was 3.34:1, unreadable at 10px).
- Tune + Fan sliders get a 16px `ext_click_area` (8–10px tracks were un-grabbable).
- CPU-temp spacing and the "FAULT:" prefix tidied to the plain status voice.

## DEFERRED — recommended, but bench-verify before/with the flash

These are real wins from the perf + UX comb, held back only because they change a
currently-working system in ways this environment cannot verify. Do them with a
build + glass check, ideally one at a time.

1. **Boot-asset RAM (~8 MB).** `assets/pono/anim/pono_flag_boot.c` (4.7 MB),
   `pono_flag_boot_intro.c` (2.7 MB), `pono_glow.c` (0.7 MB) are 32bpp
   `TRUE_COLOR_ALPHA`, resident for the whole run though only the boot screen uses
   them. Regenerate as indexed/RLE or opaque `TRUE_COLOR`, and/or cut frames; best
   structural fix is loading them from the rootfs via LVGL FS so they're
   reclaimable. (`tools/gen_pono_flag.py`, `gen_pono_spinner.py`.)
2. **Draw buffer RAM (~1 MB).** `main.cpp` `DISP_BUF_SIZE = 128*1024` elements ×
   4 bytes × 2 = full-screen 32bpp double buffer. A 1/4-screen partial double
   buffer (`480*68`) is standard LVGL and reclaims ~0.78 MB. If the panel is
   RGB565, also reconsider `LV_COLOR_DEPTH 16` (halves buffers and every asset).
3. **Main loop CPU.** `guppyscreen.cpp` loop uses a fixed `usleep(5000)` (200 Hz)
   even with the screen blanked. Sleep on `lv_timer_handler()`'s returned
   "next" (capped ~30 ms, floored higher when sleeping) to cut idle wake rate
   ~10–20x.
4. **`tune_orbit` idle CPU.** `pono_anim.cpp` runs a 60 fps infinite shadowed-dot
   orbit that keeps executing even while the Tune screen is hidden. Start it on
   show / stop on hide, drop the shadow, ~30 fps.
5. **Cal-tile dimming.** The Tune calibration tiles are gated at tap-time (confirm
   dialog) but not visibly dimmed while printing — mirror `apply_move_gates()`.
6. **Power-tile shape cue.** Reboot/Shutdown differ from the safe restart row by
   fill color alone. Add a glyph/word so it isn't color-only — but verify the body
   font carries the symbol glyph first (it may not; use montserrat for the icon).
7. **Calibration save path.** `GuppyScreen::save_calibration_coeff` writes next to
   the exe (likely read-only on the signed image) with an unchecked, non-atomic
   write. Move to a writable dir, check `is_open()`, write-temp-then-rename. (Only
   matters if `GUPPY_CALIBRATE` is in the build.)

  not live `gcode_move` state — drive them from `consume()`.
